## 7. v3 study: recall upgrade (`study_v3.py`)

Same split, eval entities and metric as section 5 (samples A and B of 1,000,000 queries each; TUNE and REPORT halves of 15,000 entities each), so every number compares directly. That is 2.4M of the 10.3M training queries; the search index is all 2.2M S1 records. Total run time about 1 h 50 min: dense channel 18 min, candidates 24, features 11, stage 1 8, ablation 8, stage 2 34, decisions 4.

**What changed**

- Candidates: the full v2 union (no rank < 10 cut) plus four new searches: a fine-tuned MiniLM bi-encoder on 'name | address' (dense; top 10, top 30 for empty addresses), a name search with relaxed frequency pruning for empty addresses (top 50), fuzzy name keys (OCR-confusion folding such as 0/o, 1/l, 5/s, 8/b and i/l, 1-deletion variants, unordered token pairs, metaphone codes) with address char 4-grams (top 10, top 30 for empty addresses), and an order-free name-key block re-ranked by address similarity. 32.9 candidates per query (was about 10).
- Stage 1: 15 new features (name-ambiguity counts, name-space rank and margin, dense and fuzzy cosines, extra search flags); 60 in total.
- Stage 2: cross-encoder on the stage-1 top 8 (was 5), 600,000 training pairs per fold (was 300,000) with empty-address queries up-weighted x3, rival features (cross-encoder rank, gap, margin, softmax) and sibling features (other queries whose top candidate is the same S1).
- Decisions: global thresholds; separate thresholds for empty and non-empty addresses; expected-F0.5 assignment per S1 entity.

**Bi-encoder:** 400,000 training queries whose S1 entity is not used by A, B or eval (3,125 steps). On its own it retrieves 0.9881 of the study true links (v2 union of three searches: 0.9825).
